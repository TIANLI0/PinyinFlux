# 云候选设计

目标是补充微软拼音的原生候选，并保证联网失败不降低本地输入的可用性。

## 公开实现参考

- [Fcitx 5 配置源码](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/pinyin/pinyin.h)：云候选默认第 2 位，永久保留占位默认关闭。
- [Fcitx 5 候选生成](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/im/pinyin/pinyin.cpp)：排除密码/敏感上下文，检查云候选与本地候选是否重复。
- [Fcitx 5 云查询模块](https://github.com/fcitx/fcitx5-chinese-addons/blob/master/modules/cloudpinyin/cloudpinyin.cpp)：最短输入长度、缓存及异步查询。
- [青简输入法官方云联想说明](https://qingjian.app/zh-hant/docs/cloud/predict)：云结果未返回、为空或超时时不改变候选，不预留空位；用户开始选词后避免晚到结果挪动选中项。其 AI 联想默认加在页尾，体现了保留本地优先级的另一种取舍。

这些是公开可核对的行为参考，不代表搜狗、百度或微软未公开的内部排序算法。PinyinFlux 没有复制上述项目代码。

## 本项目采用的行为

| 场景 | 行为 |
| --- | --- |
| 输入中、等待云结果 | 只显示本地候选，不预留空白云位，本地编号不变 |
| 输入不足 4 个字母 | 不扩展云查询，减少短码噪声和请求量 |
| 云端给出本地没有的词 | 结果到达后在微软原生第 2 位显示，带原生云图标，保留本地首选 |
| 云词与本地候选重复、无结果、超时或断网 | 候选完全不变，不出现空位 |
| 简拼、混拼、末音节未打完（`yyds`、`yuanshenqd`、`zhonggr`） | 支持；每个音节可完整或只打前缀，但必须覆盖全部输入 |
| 只覆盖部分输入（`jintianqhh` → 今天去回） | 不注入 |
| 单字、含字母数字符号的结果 | 丢弃：单字本地必有，混排字符无法逐音节对应；读音中的 `ü`/`u:` 统一为 `v` |
| 元音开头音节未用 `'` 分隔（`deepseek` 被拆成 de'e'pi'se'e'ka） | 丢弃，交给本地引擎（它会给出 `deep seek模型`） |
| 输入变化或已上屏 | 保留微软的拼音匹配、查询取消与代次检查 |
| 重复查询 | 全部词库成功的结果缓存 30 分钟；部分源失败或超时只缓存 60 秒；网络失败不负缓存，完整空结果缓存 2 秒 |
| 慢源在截止后才返回 | 不改动当前候选；最后一个源完成时把合并结果回填缓存，下次同一输入直接使用 |

4 字母、450 ms、5 字阈值和缓存时长是本项目的工程默认值，需要依据实际误候选情况调整，并非其他输入法的通用标准。

### 选哪个云词

原生响应最多提交 3 个云词。微软的过滤器（`0x1802c0cac`）会删去与本地候选重复的云词，但只有一个云词时过滤器直接返回，不做去重（由扩展的本地比对兜底，见“原生流程”第 4 条）。过滤后微软拼音只把第一个存为云摘录，显示在第 2 位（2026-11 实测：`ldsd` 过滤前后都是 3 个，`SetCOCExcerptResult` 收到 1 个）。所以多提交的词是备选：前面的词本地已有时，由下一个顶上，不会多占位置。真正要把关的是本地没有、又不该出现的词，主要是同音词。

两个词库在不同输入上的可靠程度相反（2026-10 实测）：

| 输入 | 百度 | 搜狗 |
| --- | --- | --- |
| 简拼 | 首选准确：永远的神、原神启动、北京大学、笑死我了 | 多无完整读音，首选偏通用短语：永远都是、有所期待 |
| 常用全拼 | 有时刻意避开常用词，返回同音词：`zhongguoren` → 中果人 | 首选准确：中国人 |

选词分两步：先过固定的安全门槛，再按分数排序、按自适应门槛决定提交几个。

**安全门槛（不随学习改变）**

- 读音必须与输入逐音节对齐（见上表）。搜狗的简拼结果只有音节编号、没有完整读音，同一词有其他词库核实过的读音时借用，否则丢弃。
- **全拼**：只采用被确认的词，即至少两个词库给出，且在每个给出它的词库里排前两名；更靠后的多为同音词（`nihao` 的第 3 名“泥嚎”）。词库意见不一时不显示（本地已有常用词）。没有被确认的词时，只有一个词库给出可用词、且其他词库都已应答而无可用词，才采用它的首词；有词库超时则本次不显示，迟到结果回填缓存后下次可用。
- **简拼**：5 字及以上的长简拼多为猜测（`dsjlfdslkfj` → 但是家里发大水了咖啡机），需另一个词库也给出同一词（`zhrmghg` → 中华人民共和国）。

**打分**：每个给出该词的词库贡献 `权重 ÷ (1 + 名次)`（名次从 0 起）。分数 = 最大贡献 + λ × 其余贡献之和。全拼 λ = 1，一致即信号；简拼 λ = 0.2，一致只在分数接近时起作用，因为投票会偏向通用短语（`yyds` 的“永远都是”不应压过百度首选“永远的神”）。分数最高的词排第一；之后的词分数须达到首词的“门槛”倍（默认 0.5）才提交，最多 3 个。默认权重下，优先词库的第 2 名（0.5）刚好入选，两个词库都排第 2 的全拼词（`nihao` → 你号）也入选，单一词库的第 3 名（0.33）不入选。实测提交：`ysqd` → 原神启动、有所期待、饮食清淡（原神启动已在本地时显示有所期待）；`xswl` → 笑死我了、吓死我了；`bjdx` → 北京大学。

**自适应**：扩展在每次上屏时报告这次输入实际显示过哪些云词（与本地不重复的词中，按微软存下的云摘录数取前几个）、选中了哪一个（或都没选），核心据此学习。提交了但没显示的备选不算被忽略。全拼和简拼分开学习：

| 学什么 | 怎么学 | 效果 |
| --- | --- | --- |
| 词库权重（优先级） | 每个显示过的词，给出它的词库按 `1 ÷ (1 + 名次)` 记一次“展示”；被选中的词再记一次“命中”。展示按屏幕位置打折（第 1、2、3 个云位分别计 1、0.7、0.5），抵消越靠前越容易被选的偏差；目前微软只显示 1 个，只用到第 1 档。权重 = 配置优先级先验（第 i 个词库为 `1 ÷ (1 + i/4)`）×（该词库命中率 ÷ 所有词库合计命中率），后一项限制在 ¼ 到 4 倍。各词库命中率以合计命中率起步，相当于先有 50 次展示（合计命中率同样以 0.2 起步）。只比相对值：大多数上屏选的是本地词，实际命中率很低，若按固定基准换算，所有词库都会被压到下限，学到的顺序就丢了 | 连续约 3 次都选第二词库的词，它的词就排到第一 |
| 门槛（数量） | 统计答案中首词之后的词被选中的比例（目标 8%，同样有 50 次的先验）。门槛 = 0.5 × √(8% ÷ 实际比例)，限制在 0.25 到 0.95 | 后面的词常被选中就降低门槛、多给；总被忽略就提高门槛、只给最好的一个 |

- 按答案中的名次而不是屏幕位置判断“首词之后的词”：首词常是被过滤器隐藏的本地词（`wangluo` → 网络被隐藏，王洛显示在最前），王洛总被忽略时门槛会升高，它就不再出现。
- 每次学习先把旧计数乘以 0.995（约 140 次后减半），习惯变化后能跟上；只出一个词时，后面词的计数也随之衰减，门槛会慢慢回到 0.5，后面的词重新出现、重新接受检验。
- 缓存保存各词库的原始答案，每次查询都用当前学到的权重重新排序，学到的结果立即生效，不必等缓存过期。
- 隐私：扩展只把答案的哈希（各词 UTF-16 的 FNV-1a）和序号放进共享内存；核心用最近 32 个答案的哈希找回各词出自哪个词库、排第几。保存到 `%LOCALAPPDATA%\PinyinFlux\ranking.ini` 的只有按词库、按输入类型的衰减计数，不含输入内容。微软拼音不记录输入历史的场合（`SetPrevPrimitive` 返回 S_FALSE）不学习。当前学习状态见 `/status` 的 `ranking`：各类型的门槛与各词库的命中率。
- 原生查询等待全部词库（总上限 450 ms）。因为等待期间不预留空位，等待不会移动本地候选。

## 原生流程

以下函数、偏移和通知位最初在 x64 10.0.26100.9767 上由公开 PDB 与反汇编核对。其他版本由核心自动适配（`native_symbols.cpp`）：

- 函数地址按公开符号名查找（如 `ChxIME::CandidateHandlerConversionPinyin::CheckCOCTriggerRule`、`ChsQueryHandler::IsExpiredDuringCloudDelay`）。PDB 按组件调试目录里的 GUID 从微软符号服务器下载一次后缓存，由系统 `dbghelp.dll` 读取。
- 字段偏移从使用它们的指令读出：触发规则的 `cmp byte ptr [rdi+…]`、设置接口的虚表调用、`SetCOCExcerptResult` 的 `lea r14,[rcx+…]`、拼音池与基类偏移、请求锁的 `cmp byte ptr [rip+…],0` 等。
- `OnProductItemChanged` 必须仍然检查 `0x1000`、`0x400`、`0x8` 这三个通知位，否则不安装。
- 核心记录每个函数在磁盘上的前 16 字节；扩展在宿主中逐一比对，不一致（版本不同或已被其他工具改动）就不挂该函数。必需的挂钩缺一个就报告不支持；诊断挂钩和不用于桌面候选的 ChsIME 路径可缺。
- ChsProxyDS 的请求重定向只依赖 WinHTTP 导入表，任何版本都可用；本地缓存、响应记录和输入停顿等待的挂钩在地址可确认时才启用。
- 微软响应记录、本地候选记录的文字读取有异常保护；本地候选文字偏移同样从触发规则的 `movzx edx, word ptr [rax+0Ah]` 读出，读不出时不做本地比对，只依靠微软自己的去重。
- 离线时只能使用内置的已校验版本地址表。

### Windows 更新后的适配

Windows 更新可能改动微软拼音，而上面的符号和指令特征未必都能察觉（例如记录布局变了，入口字节和特征却都还对得上）。注入的是输入法宿主（ctfmon），出错就意味着整个系统打不了字，所以注入要过四道关（`native_injector.cpp`、`native_compat.cpp`）：

1. **解析可重试**：区分“缺符号”（符号服务器连不上，通常是更新重启后网络还没就绪）和“特征对不上”。缺符号时每分钟重试，不需要重启核心；特征对不上则判定为不支持。
2. **注入前自检**：首次注入某个组合（InputService、ChsProxyDS、ChsEM 的版本 + 扩展 DLL 的哈希）之前，核心以 `--preflight` 启动一个子进程：把已安装的组件映射进子进程（不执行其代码），按与宿主完全相同的方式装上扩展，经被改写的 WinHTTP 导入表发出一次 Bing 云请求并确认到达本地监听，再停止并确认所有槽位恢复。子进程的 HKCU 换成一个空的易失键，使检查不受用户的输入法设置影响（双拼时扩展按设计不重定向，否则这一步必然失败）。子进程崩溃、超时（20 秒）或任一步失败都不注入。结论写入 `%LOCALAPPDATA%\PinyinFlux\compat.ini`，键中含自检的修订号（自检逻辑修正后旧结论作废），同一组合以后直接沿用，所以每次 Windows 或 PinyinFlux 更新后只检查一次，约 2 秒。
3. **注入后崩溃保护**：注入后 10 分钟内，宿主以异常码（`0xC…` 开头，如访问违例）退出算一次崩溃；同一组合累计 2 次即判定为不兼容，停用所有宿主中的扩展，不再注入。
4. **待重启识别**：宿主里加载的组件与磁盘上的不同：若磁盘上的也已不是解析时的版本，说明核心运行期间 Windows 换了文件，重新解析；否则是更新已安装、等待重启，此时不注入，状态提示重启。

状态见 `/status` 的 `nativeCompat`（`resolving`、`waitingSymbols`、`checking`、`verified`、`unsupported`、`crashed`）与 `nativeRestartPending`，设置界面按状态说明原因和下一步。“重新检查”会删除 `compat.ini` 并重启核心。

扩展用 MinHook 的批量接口装卸钩子：MinHook 每应用一次改动都要冻结宿主的其他线程（之前还要对全系统的线程做一次快照），逐个应用时十几个钩子要 1 秒以上，批量应用约 150 ms。

### 双拼

双拼模式下微软拼音发往云端的是按键原文（`nihk` 表示 ni hao，`ysyr` 表示 yong yuan），词库会把它当作全拼或简拼，查出错词（`nihk` → 你好看）。PinyinFlux 不适配双拼（按各双拼方案换算成全拼不在范围内）：扩展在双拼模式（`HKCU\Software\Microsoft\InputMethod\Settings\CHS` 的 `Enable Double Pinyin`）下不触发、不重定向，微软自带的云候选保持原样；核心对此时到达的请求也返回空结果。打字统计照常。模糊音不需要处理：读音须与实际敲的字母逐音节对齐，模糊匹配到的词会被拒绝，不会出错词。

### 出词耗时

扩展记录每个显示出来的云词从最后一次按键到出现的时间，分三段：微软的输入停顿等待（ChsProxyDS 的 `[this+0x214]`，本机为 100 ms，实测平均约 115 ms）、核心与词库应答（约 60–90 ms）、重放（约 15 ms），合计约 200 ms，九成在 300 ms 以内。网络只占其中一小段，预取最多省下这一段，却要把更多拼音发给词库，因此没有做；`nativeTiming.missed` 统计“请求还没应答就上屏”的次数，留作以后判断的依据。

1. **触发**：云查询与接纳使用上游 `CheckCOCTriggerRule` 的正常路径。保留原生同意状态、云开关及输入范围检查；替换配额、网络成本和本地置信度等触发启发式。不能仅给下游通知加位，否则输入法可能发出请求却不接纳返回候选。
2. **占位**：微软每次重新生成候选（通知 `0x8`）时，用 `CreateCOCPreloadingSuggestionList` 在第 2 位插入空白云占位；结果到达（通知 `0x1000`，实际为 `0x1c00`）时替换该占位。没有占位时到达的结果被丢弃（`E_UNEXPECTED`，槽位索引为 -1）。空结果或全被去重的结果会留下只有云图标的空白占位，且之后不会移除。
3. **延后占位**：输入期间占位工厂返回零元素列表，候选不变。结果到达时，若其中有本地候选列表里没有的词，就在同一线程上对同一拼音重放一次按键通知（`0x8`、`0x22000`，依次发给候选与界面两个监听者），这次放行原生占位，并丢弃这次没有占位可填的到达。重放出的查询由核心缓存立即回答，跳过 ChsProxyDS 约 100 ms 的输入停顿等待（同样持有其单请求锁）后填入占位。实测空白最多一帧（约 16 ms）。没有可显示的新词时不重放，候选从不出现空位。
4. **本地候选比对**：在触发规则里按原生规则读取本地候选的方式（`GetAt`、信息接口、`0x80` 掩码；记录 `+0x0a` 为以 0 结尾的文字偏移，`+0x0c` 为下一字段偏移）读取最多 256 个本地候选，与响应记录 `+0x20` 的候选文字比较。全部重复时不重放占位，作为单个云词绕过原生去重时的保障。
5. **缓存**：微软私有云缓存会保留旧配置或错误结果，注入期间一律视为未命中，改用核心按词库区分的缓存。

原生位置和选词学习继续由微软管理：云词显示在第 2 位，选中后由微软拼音自己学进本地词库，下次作为本地候选出现（因而被过滤器去重）。PinyinFlux 只学习云词之间的排序和数量，不保存词本身，也不改动本地候选的排序。

## 验证

`cloud_priority_deadline_cache` 验证等待全部词库、全拼分歧不出词、无效读音回退、借用读音、简拼/混拼/末音节对齐、元音分隔、长简拼需要第二来源、按分数和门槛给出多个云词、选择反馈调整词库优先级与门槛（全拼、简拼分开；被隐藏首词的情形）、缓存答案按新权重重新排序、学习状态重启后保留、成功缓存、失败重试、截止及迟到结果回填。`native_response_parser` 用微软真实解析器确认全拼与简拼响应都生成带完整读音的转换记录，多个云词按提交顺序各生成一条。`native_redirect_restore` 等测试覆盖网络重定向、停止恢复，以及核心重启后扩展连接到新的共享内存。`native_preflight` 在本机组件上运行注入前自检，`native_preflight_rejects_bad_extension` 确认无效扩展被拒绝，`native_preflight_double_pinyin` 确认用户开着双拼时自检仍然通过。另有真实联网冒烟测试。

端到端验收在测试窗口 `PinyinFluxImeTest.exe` 中用微软拼音实际输入（开发时曾用模拟按键加候选栏截图识别批量检查，只观察不上屏，不影响自学习）：`yyds`、`yuanshenqd` 出现云词；`zhongguoren`、`deepseekmoxing`、乱打字母和 3 字母短码候选不变；等待期间无空位。
